# AdSense 저가치 콘텐츠 감사와 후속 정확성 개선 — 2026-10-01

## 판정

**아직 재심사를 요청할 단계는 아니다.** 공개 문구·산식 설명·사례 수치·데이터 부족 처리를 개선해 Hosting-only로 배포했고, 라이브 18개 경로와 편집 사실성 검사를 모두 통과했다. 운영자가 학습 자료를 최종 검토했다는 증거, 현재 데이터 갱신의 안정성, 실제 사용자 관심, Search Console 소유권, AdSense 계정 상태는 아직 확인하지 못했다. Google의 심사 결과나 승인 가능성을 보장할 수 없다.

## 공식 기준을 이번 사이트에 적용한 방식

- [AdSense 페이지 준비 안내](https://support.google.com/adsense/answer/7299563?hl=ko)는 고유하고 관련성 있는 본문, 원본 콘텐츠, 명확한 탐색과 사용자에게 유용한 경험을 준비 요소로 안내한다.
- [AdSense 콘텐츠·사용자 환경 안내](https://support.google.com/adsense/answer/10015918?hl=ko)와 [게시자 콘텐츠가 없는 화면 정책](https://support.google.com/publisherpolicies/answer/11112688?hl=ko)은 방문자가 찾는 고유 콘텐츠, 정기적인 갱신, 유용한 화면을 강조하며 가치가 낮거나 직접 검토·선별하지 않은 자동 생성 콘텐츠 화면에는 광고를 허용하지 않는다고 명시한다. [복제 콘텐츠 정책](https://support.google.com/publisherpolicies/answer/11190248?hl=ko)은 다른 출처를 새로운 가치 없이 재작성·삽입하는 화면을 금지한다.
- 이 정책은 규칙 기반 계산, 통계 검색, 데이터 도구를 범주만으로 금지하지 않는다. 사용자는 MesuGak의 분석 규칙을 실제 분석에 사용한다고 설명했고, 코드도 지표별 판정·점수·근거와 결측 처리 규칙을 구현한다. 계산이 코드로 수행된다는 사실만으로 이를 AI 생성 글이나 저가치 콘텐츠라고 단정하지 않는다. 다만 결과가 자동 갱신되는 화면에 광고를 게재할 경우 직접 검토·선별 정책의 적용을 별도로 확인해야 한다. 개별 종목 결과의 사람 검토 여부는 확인하지 못했으며, 현재 /analysis에는 광고가 없다.
- [AdSense 거절 도움말](https://support.google.com/adsense/answer/81904?hl=ko)는 사이트의 페이지 전반을 검토할 수 있고, 독창적이거나 충분한 사용자 가치가 없는 콘텐츠가 저가치 사유가 될 수 있다고 설명한다.
- [Google 게시자 정책](https://support.google.com/adsense/answer/9335564?hl=ko)은 광고가 표시되는 화면에도 정책이 적용된다고 명시하며, Google Search 스팸 정책은 검색 순위·노출을 위한 별도 정책이다. 두 정책은 겹치는 내용이 있지만 검색 품질 권고 전체를 AdSense의 독립 승인 규칙으로 취급하지 않는다.
- [Google의 사용자 우선 콘텐츠 안내](https://developers.google.com/search/docs/fundamentals/creating-helpful-content?hl=ko)는 검색 품질 자체 평가 자료다. 이 사이트처럼 주식·가치지표를 다루는 곳은 금융 안정성에 영향을 줄 수 있는 YMYL 주제로 볼 수 있어 출처·작성 주체·경험·검토 신뢰를 더 엄격히 살핀다. 이 안내가 AdSense 승인 공식이나 자격 요건을 보장하지는 않는다.
- 확인한 AdSense 공개 안내에는 승인에 필요한 최소 글자 수·페이지 수가 제시되어 있지 않다. 페이지 수나 글자 수를 부풀리지 않고, 각 페이지가 독자 질문을 해결하는지, 내용이 실제로 정기 확인·정정되는지, 거절 안내가 요구한 실제 사용자 관심을 설명할 수 있는지 따로 확인한다. 프로젝트 내부 통과선은 Google 공식 수량 기준이 아니다.

## 발견 사항과 이번 수정

### 1. 검증되지 않은 운영 주장 — 수정·배포 완료

이전 공개 문구는 운영자가 페이지를 직접 검토했다거나 학교 서버가 정해진 간격으로 갱신한다고 읽힐 수 있었다. 기존 실행 기록으로 해당 검토와 서버 주기를 입증할 수 없었다. 추가 전수 검색에서는 사례 수업 소개의 운영자 작성 주장과 법적 안내 페이지의 “마지막 검토일”도 확인했다. 사례 저자 주장은 제거하고, 법적 안내 날짜는 사람이 실제 법률 검토를 했다는 의미가 아니라 문서의 수정 날짜임을 나타내도록 바꿨다. 현재는 공개 기준일만으로 제공기관이나 서버의 현재 상태를 확인할 수 없고, 이전 결과가 남아 있을 수 있다고 설명한다. 실제 검토·갱신 기록이 확보되기 전에는 같은 주장을 다시 추가하지 않는다.

### 2. 점수 산식 설명과 구현 간 차이 — 보완·배포 완료

방법론을 `functions/strategy_engine/scoring.py`와 대조했다. 현재 구현은 볼린저 밴드 25, 이동평균 지지 20, 일목균형표 20, RSI 10, 거래량 10의 기본 비율을 사용한다. 필요한 입력이 빠진 요소는 제외하고 남은 가중치 합으로 다시 나눈다. 볼린저 하단보다 종가가 낮으면 15를 감점한 뒤 0~100으로 제한하고 소수 둘째 자리까지 반올림한다. 이동평균 지지 점수는 종가가 MA 위인지 단순 계산하는 규칙이 아니며, 가치지표 PER·PBR·ROE는 현재 종합점수에 들어가지 않는다.

공개 방법론 페이지에 이 규칙과 가상 산술 예시를 추가했고, 원시 입력값과 요소별 점수가 공개되지 않아 방문자가 공개 화면만으로 종목별 점수를 재현할 수 없다는 한계도 밝혔다. 학습 홈과 분석 안내에서도 점수를 상승 확률처럼 표현하지 않고 방법론으로 연결한다.

### 3. 지표 원리와 V2 계산 설정의 차이 — 명시·배포 완료

6개 지표 수업과 PBR 사례에 관련 원자료 링크를 달고, 일반 정의와 실제 구현 설정을 구분했다. 이동평균은 현재 종가를 포함한 5·20·60·120일 단순평균이며, 일목균형표는 9·26·52일 고가·저가 중간값과 26거래일 이동을 사용한다. 볼린저 밴드는 V2의 `rolling.std()` 기본값인 표본 표준편차(`ddof=1`)를 쓰지만 [John Bollinger의 기본 정의](https://www.bollingerbands.com/bollinger-bands)는 모집단 표준편차를 쓴다고 명시한다. 이 차이를 방법론과 예시에 공개했으며, 점수 결과를 바꾸는 전략 엔진은 이 콘텐츠 작업에서 수정하지 않았다.

RSI는 `alpha=1/14`, `adjust=False`, 최소 14개 유효 변화 설정을 사용하고 9기간 단순평균을 보조선으로 둔다. [Pandas EWM 문서](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.ewm.html)의 재귀 계산 설명을 연결하고, 초기화 설정에 따라 플랫폼의 첫 값이 다를 수 있다고 적었다. 상대 거래량은 현재 거래량을 현재 일을 포함한 최근 20개 관측치 평균으로 나눈다고 밝혀 계산 차이를 숨기지 않는다.

### 4. 조건 실험실의 조작 안내 — 수정·배포 완료

실제 화면에서 선택 조합을 바꾸면 긍정 근거와 주의 근거가 갱신되고, 모두 해제하면 안내 상태로 돌아오는 것을 확인했다. 조작 설명은 “두 개 이상” 선택하라고 했지만 하나만 선택해도 정상 작동했다. 설명을 “하나 이상”으로 고쳤고, 화면 지시와 실제 동작이 어긋나지 않는지 정적 콘텐츠 검사에 추가했다. 기준일 사례는 방문자가 볼 수 없는 서버 감시 상태 대신 화면의 지연·데이터 부족 안내와 제공기관의 공개 날짜를 확인하도록 바꿨다.

### 5. 사례 수치와 데이터 부족 설명 — 구현·테스트 대조 후 보완

사례 수업의 여덟 질문을 다시 읽고 PBR 비교를 포함한 일곱 사례에 가상 입력값과 단계별 판정 근거를 추가했다. 볼린저 상방 확장·거래량 약화, 이동평균 지지 교차, RSI 회복, 구름대 아래 상태는 점수 코드에 같은 값을 넣어 결과가 각각 `+90`, `−20`, `−35`, `+35`, `−35` 구성요소 점수와 일치하는지 확인했다. 전체 종합점수로 오해하지 않도록 다른 지표와 감점이 별도로 적용된다고 밝혔다.

사례 08과 방법론·용어집은 서로 달랐던 두 상황을 분리했다. `analyze_stock`은 입력 일봉 행 120개 미만에서 새 payload를 만들지 않고 분석 작업은 자료 부족 실패를 기록한다. 최소 행 수를 채운 뒤 개별 지표가 계산 불가 상태가 되면 해당 가중치를 제외하고 나머지 가중치 합으로 재정규화한다. `functions/tests/test_scoring_risk_analysis.py`에 119/120행 경계와 사례 점수 계산 회귀 테스트를 추가했다. 새 분석 결과 부재를 공개 화면이 항상 별도 상태로 표시한다고 주장하지 않도록 체크 문구도 바꿨다.

### 6. 실제 지속 관리와 독자 관심 — 증거 대기

수정 날짜와 오류 문의를 표시하는 것만으로 지속적인 큐레이션이나 독자 관심이 입증되지는 않는다. 운영자가 실제 내용을 확인한 편집 기록, 다음 정상 갱신 확인, 신뢰할 수 있는 유기적 이용 기록이 필요하다. 이를 페이지 수 증가나 구매 트래픽으로 대체하지 않는다.

### 7. 금융 주제의 작성·검토 신뢰 — 운영자 사실 확인 대기

이 사이트는 종목별 기술 조건과 PER·PBR·ROE 같은 금융 정보를 다룬다. 현재 `/about`은 개인 프로젝트와 문의 주소를 밝히지만, 공개된 사람 이름·금융 분야 경험·실제 편집 검토자는 확인되지 않는다. 계산 코드 대조와 자동 테스트는 구현 정확성의 근거이지 금융 전문성이나 편집자 검토 증거가 아니다. Google Search의 사용자 우선 콘텐츠 안내는 출처, 작성자·사이트 배경, 전문성, 확인 가능한 오류를 자체 점검 항목으로 제시하고 YMYL 주제에서 신뢰 신호를 더 중시한다고 설명한다. 이는 검색 품질 안내이며 AdSense의 별도 자격 기준은 아니다. 재심사 전 운영자가 실제 작성·검토 주체와 공개할 수 있는 경력을 확인하고, 자격이나 전문가 검토를 주장하려면 이를 뒷받침하는 사실이 있어야 한다. 사실 자료가 없으면 신뢰를 꾸며내지 말고 이 항목을 미해결로 남긴다.

### 8. 조건 실험실의 방향 편향 — 수정·라이브 검증 완료

`/learn/lab`은 볼린저 밴드 폭의 확장을 긍정 조건으로 분류했고, 하락 방향 확장이라는 한계는 별도 주의 조건이 선택될 때만 나타났다. 밴드 폭은 변동성 크기를 나타내며 방향 자체를 정하지 않으므로, 한쪽 해석만 보여주는 동작은 교육 정확성을 떨어뜨렸다. 조건의 사전 긍정·주의 분류를 없애고 선택한 각 조건에 가능한 해석과 한계를 함께 보여주도록 수정했다. 가상 RSI·상대 거래량 사례에 단계별 근거·한계·다음 확인 항목을 더했고, 점수나 매매 추천은 계산하지 않는다고 명확히 했다. `npm run test:live`에서 공개 경로 18개와 편집 사실성 검사 실패 0건을 확인했으며, 실제 Hosting 페이지에서 밴드 확장 조건을 선택해 변동성 해석과 방향 불확실성, 하락 방향으로도 넓어질 수 있다는 주의 문구가 동시에 표시되는 것을 확인했다.

### 9. 규칙 기반 분석과 자동 생성 콘텐츠 구분 — 기준 재정리

앞선 진단에서 규칙에 따른 종목 분석을 자동 생성 글과 너무 가깝게 묶어 표현했다. 사용자는 이 분석 규칙을 실제 분석에 사용한다고 확인했다. 현재 코드는 볼린저 밴드 25%, 이동평균 지지 20%, 일목균형표 20%, RSI 10%, 거래량 10% 가중치와 각 지표의 판정 근거를 적용하고, 사용할 수 없는 지표는 점수 합산에서 제외한 뒤 남은 가중치를 다시 정규화한다. 이것은 운영자가 정한 분석 방법을 데이터에 적용하는 도구이며, 작성된 문장을 대량 생성하는 것과는 다른 기능이다. 동시에 결과 자체는 코드로 갱신되므로 개별 종목 결과를 운영자가 매번 직접 검토·선별하는지는 확인하지 못했다.

따라서 계산 자동화 자체를 저가치 원인으로 단정하지 않는다. AdSense 거절 사유에 구체적인 URL이 없고 /analysis는 현재 무광고이므로 이 화면의 광고 재고가 거절 원인이었다고도 확인하지 못했다. /analysis의 noindex는 색인 범위 선택이며 품질 판단이 아니다. 앞으로는 분석 도구의 방법론·데이터 출처·기준일·해석 범위·운영 안정성·실제 이용 가치를 확인하고, 실제 광고를 둘 화면에는 직접 검토·선별 정책을 적용한다. OP.GG처럼 통계 검색과 빌드 안내를 중심으로 하는 서비스도 사용자에게 구체적 문제 해결과 업데이트된 데이터를 제공하면 자체 제품 가치를 만들 수 있지만, 다른 사이트의 존재나 규모는 심사 통과의 보증이 아니다.
