# 2026-10-16 대회 과거 일봉 재사용 개선

## 확인한 사실

14:51 KST 한투 계좌 조회에서 오늘 체결·보유·미체결은 0이었다. 로컬에는 09:30 매수 신호 1건이 있었지만 매매불가 종목 거절로 `FAILED`였다. 당시 heartbeat의 일봉 준비 수는 감시 39개 중 9~10개였다. 이것만으로 과거 일봉 조회 자체가 불가능했다고 설명한 것은 부정확했다.

서버에서 같은 감시 39종목의 gzip 캐시를 **API 호출 없이** 읽은 결과 모두 유효한 완성 과거 봉을 갖고 있었고, 전체 검증은 약 0.22초였다. 오늘 장전 검사는 08:32:35에 대상 2,754개 중 2,717개 성공·37개 실패로 처리 완료됐다. 실패 종목은 유효 점수가 없으며 완료 개수에 포함하지 않는다.

점수는 원래도 장전 검사에서 KIS 이력으로 계산해 후보 파일에 저장하고, 장중에는 과거 완성 봉과 WebSocket 당일 진행 봉으로 다시 계산했다. 문제는 자료의 부재로 단정할 상황이 아니라 **자료 준비·재사용 경로**였다.

## 기존 구조의 문제

- `queue_histories()`가 감시에서 빠진 종목의 메모리 이력을 제거했다. 재편입되면 다시 준비해야 했다.
- 디스크 캐시 적중과 느린 REST 보충이 동일 semaphore 경로를 사용했다. 일부 누락 종목의 조회가 다른 종목의 캐시 사용까지 지연시킬 수 있었다.
- 교체 때 `asyncio.to_thread()` 작업을 취소해도 실행 중인 HTTP thread는 종료되지 않는다. 반복 교체 시 불필요한 작업과 executor 점유가 누적될 수 있었다.
- 마지막 점수는 전략 상태에 남아 있었지만 관측 시각이 없었고, 현재 감시에서 빠지면 heartbeat의 `lastScores`가 비어 보여 점수 자체가 없다는 오해가 가능했다.

기존 실행의 모든 지연을 특정 API 요청 하나 때문이라고 입증한 것은 아니다. 위 항목은 직접 확인한 코드 경로이며, 캐시 유효성은 별도 서버 실측이다.

## 적용 구조

```text
장전 KIS 전체 검사 → 종목별 완성 일봉 gzip 캐시
                         ↓
감시 대상 선택 → 로컬 캐시 일괄 준비 → WebSocket 구독
                         ↓                    ↓
                  메모리에 유지        당일 진행 봉 갱신
                         └─────── 점수 계산 ────┘

캐시 누락·오래됨·손상 → 별도 단일 REST 보충 → 캐시/메모리 반영
```

### 과거 봉

`contest_market_data.load_cached_score_history()`는 브로커 호출 없이 KIS 출처·봉 수·유효 OHLCV·준비 날짜를 검사한다. 현재 세션의 봉은 완성 과거 봉에서 제외한다. 이전 캐시라도 직전 평일 완성 봉까지 있으면 장중 REST 재조회 없이 쓸 수 있다. 휴장 직후처럼 직전 평일 봉이 없는 경우에는 오늘 KIS 검사 완료 marker가 있어야 로컬 캐시로 인정한다.

`load_cached_score_histories()`가 필요한 종목을 일괄로 읽는다. 감시 구독 전 `load_watch_histories()`에서 이 경로를 먼저 완료한다. 이미 메모리에 있는 이력은 재조회하지 않고, 감시 교체 후에도 당일 후보 universe 안에서 유지한다. 후보에서 제거되고 보유·감시도 아닌 이력은 정리해 메모리가 무제한 증가하지 않게 했다.

### 누락분 보충

실제 캐시 누락·손상·오래된 자료만 기존 KIS 조회 경로로 보충한다. 보충은 1개씩 실행하며 감시 교체 때문에 실행 중인 REST 작업을 취소하지 않는다. 대기 중인 작업은 실행 차례에 현재 필요한지 다시 확인한다. 조회 실패는 유형을 기록하고 300초 뒤 재시도할 수 있다. 검사에서 이미 `scoreUnavailable`로 판정한 비보유 종목은 실시간 후보에서 제외해 무의미한 재조회·감시를 줄인다.

### 현재 시세와 마지막 점수

현재 시세를 받을 때 기존 공용 지표 계산기로 오늘 진행 봉을 계산한다. 과거 봉 원본은 바꾸지 않는다. 실제 시세가 아직 오지 않은 종목은 이력 준비가 끝나도 현재 점수가 없는 상태다. 장전 점수를 현재 실시간 점수로 위장해 주문하지 않는다.

`liveScores`와 함께 `liveScoreObservedAt`을 당일 전략 상태에 저장한다. 감시에서 빠져도 최근 관측 점수·시각은 유지하고 재시작 때 복원한다. 변경 전에 만들어진 점수에는 시각이 없으므로 `null`로 표시하며 임의로 현재 시각을 붙이지 않는다.

heartbeat에 다음 진단 항목을 추가했다.

| 항목 | 의미 |
|---|---|
| `scoreHistoryReadyCount` | 현재 감시 중 완성 과거 이력이 준비된 수 |
| `historyMemoryCount` | 감시에서 빠진 종목까지 포함한 재사용 메모리 이력 수 |
| `historyLoadPendingCount` | REST 보충 작업 대기·실행 수 |
| `watchHistoryMissingCodes` | 감시 중 과거 이력이 준비되지 않은 코드 |
| `historyCacheLoadSeconds` | 최근 감시 갱신에서 로컬 캐시 준비에 걸린 시간 |
| `historyRestFillCount` | 이번 프로세스에서 누락 이력을 보충한 횟수 |
| `observedScoreTop` | 마지막 관측 점수 상위 10개·관측 시각·현재 감시 여부 |
| `historyPolicy` | `disk_cache_before_subscribe_keep_completed_candles` |

기존 매수 `>60`, 고정 감시 `>=55`, 매수 이후 최고가 대비 1.8% 절반·3% 잔량, 시장가 주문, 보유·진행 주문 보호, 현재 최대 보유 3종목과 실행 시간은 변경하지 않았다.
