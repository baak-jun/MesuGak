# 2026-10-15 대회 최신 일봉과 마감 메일

## 확인한 문제

기존 대회 전체 검사는 공공데이터 일봉을 사용했다. 10월 15일 06:30~07:27에
2,755개를 검사해 2,718개 성공·37개 데이터 부족으로 완료됐지만 원천 일봉은
10월 13일이었다. 장중 점수는 이 이력에 한투 당일 진행 봉을 붙여 계산해
10월 14일 봉이 누락될 수 있었다. 현재 감시·랜덤 탐색 점수와 전체 일봉 순위도
분리해서 보고해야 한다. 낮은 감시 점수를 시장 전체 상태로 해석하지 않는다.

한투 모의 API 기간별 시세를 직접 조회해 삼성전자의 10월 15일 진행 봉과
10월 14일 완성 봉이 정상 반환되는 것을 확인했다. 공식 API는 실전·모의 모두
호출당 최대 100개 봉을 반환한다.
[한투 공식 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_daily_itemchartprice/inquire_daily_itemchartprice.py).

## 대회 데이터 경로

- `strategy_engine/contest_market_data.py`는 한투 수정주가 일봉만 사용해 최대
  180개 유효 봉을 캐시한다. 부족하면 이전 구간을 한 번 더 조회한다. 완성 봉이
  120개 미만이면 점수를 만들지 않는다. 기존 공공데이터 캐시는 한투 이력으로
  재사용하지 않는다. 이전 날짜의 수정주가 변경이 감지되면 과거 구간도 다시 받는다.
- 실시간 점수 계산 시 오늘 이전 한투 봉을 기준으로 하고, 오늘 봉은 WebSocket
  가격·시가·고가·저가·누적 거래량으로 계산한다. 오늘 REST 봉과 실시간 봉을
  중복으로 두 번 넣지 않는다. 기존 공공 이력으로 만든 장중 점수 캐시는 무효화했다.
- 대회 전용 결과는 `runtime/checkpoints/contest_candidates_KR.json`, 한투 이력은
  `runtime/kis-history/`에 둔다. 종목 코드·이름·시가총액 목록은 기존 공공 종목
  목록을 사용하지만, 이 경로의 가격과 점수는 한투에서 새로 계산한다.
- 사이트 공개 분석·Firebase 결과는 기존 공공데이터 경로를 유지한다. 대회 한투
  원시 일봉이나 전체 결과를 공개 사이트에 게시하지 않는다.
- 공유 SQLite 요청 간격을 적용해 별도 프로세스인 전체 검사·매매·계좌 보고도
  같은 앱 요청 한도를 함께 지킨다. 주문이 대기하면 대량 일봉 조회를 뒤로 미룬다.
  일봉 HTTP 요청은 5초 제한, 명시적 요청 제한 거절 시 기존 감속·재시도를 유지한다.
- 평일 05:00에 대회 한투 전 종목 검사를 시작한다. 기존 06:30·07:30·08:30 예약은
  동일 잠금으로 중복 실행을 피하고 미완료·실패 항목을 이어서 시도한다. 장전 조회는
  08:50까지로 제한한다. 첫 한투 이력 채움은 12:15에 시작했으며 오늘만 18:00까지
  읽기 전용 스캔을 이어간다. 매매 시간·시장가·60점 초과 매수 기준은 바꾸지 않았다.
- 첫 콜드 캐시에서는 분석 준비 전 랜덤 교체를 막는다. 고정·보유 보호 이후 아직
  점수가 없고 이력 오류도 없는 종목은 API 간격·감시 수에 따라 120~300초 범위에서
  준비 시간을 주며, 이후에는 무조건 고정하지 않는다. 점수가 나온 비보유 종목은
  기존 55점 미만 교체·55점 이상 편입 규칙을 적용한다.
- 전체 스캔은 점수가 준비된 종목, 조회 대기, 계산 불가를 구분한다. 중간 결과는
  첫 항목과 이후 10개마다 원자적으로 저장한다. 전체 검사 시각과 각 종목의 시각은
  다를 수 있으며 전 종목이 동시에 실시간 재계산됐다고 보고하지 않는다.

평일 한국시간 15:40에 기존 수신 주소로 보내고, 미완료 때 15:45·15:50·15:55 및

않는다. 계좌·주문 조회가 실패하면 오류 메일을 한 번 만들고 정상 보고 키는 소모하지
