# MesuGak V2 모바일 UI 전환 계획

## 문서 상태

- 작업 브랜치: `codex/mobile-ui-plan`
- 기준 브랜치: `feature/v3-kis-api`
- 기준 커밋: `32e92c2 feat: add interactive modal for analysis reasons`
- 상태: 1~4단계 구현 완료 · 학습/광고 정책 코드와 로컬 반응형 검증 완료 · 5단계 운영 활성화는 실제 AdSense 승인·CMP 스크립트 입력 후 진행
- 데이터 범위: 프론트엔드 표시와 상호작용만 변경한다. KIS 분석, Firestore 스키마·규칙, 공개 데이터 발행 로직은 변경하지 않는다.
- 작업 트리 주의: 브랜치 생성 시점의 미커밋 변경사항을 그대로 보존하고 있다. 사용자의 확인 없이 기존 변경사항을 되돌리거나 한 번에 커밋하지 않는다.

구현 메모: 기존 `styles.css`와 `research.css`에 흩어진 규칙을 이번 작업에서 전면 재작성하지 않고, `research.css` 마지막에 모바일 우선 호환 블록을 추가해 회귀 범위를 줄였다. 추후 CSS 정리 작업은 별도 단계로 분리한다.

## 1. 목표

MesuGak V2의 공개 분석, 관리자 분석, 모의투자 성과, 교육 팝업, 법적 문서를 휴대전화에서 가로 스크롤과 긴 선행 목록 없이 사용할 수 있게 만든다.

핵심 목표는 다음과 같다.

1. 휴대전화에서는 `종목 찾기 → 종목 선택 → 분석 읽기 → 목록으로 돌아가기` 흐름을 한 화면씩 명확하게 제공한다.
2. 공개 화면의 분석 내용과 법적 고지는 데스크톱과 동일하게 유지하되, 읽는 순서와 터치 조작을 모바일에 맞춘다.
3. 관리자 전용 차트와 모의투자 표도 페이지 전체가 넘치지 않게 제한된 영역 안에서 사용할 수 있게 한다.
4. 기존 React 상태와 CSS를 재사용하고, 모바일 전용 라우터·UI 프레임워크·외부 반응형 라이브러리는 추가하지 않는다.
5. 모바일 변경 후에도 데스크톱 레이아웃과 공개/관리자 데이터 경계가 유지되어야 한다.

## 2. 이번 작업에서 하지 않는 것

- 네이티브 앱 또는 PWA 설치 기능
- 모바일 전용 백엔드 API와 Firestore 컬렉션
- 데스크톱/모바일 컴포넌트의 전체 이중 구현
- 새로운 CSS 프레임워크, 상태관리 라이브러리, 테스트 프레임워크 도입
- 차트 계산식, 점수 계산, 종목 정렬 규칙 변경
- 광고 승인 전 실제 광고 활성화
- 브랜드·색상·교육 문구의 전면 재작성

## 3. 현재 구조에서 확인한 문제

### 3.1 전체 화면 구조

- `.terminal-shell`은 데스크톱에서 330px 종목 목록과 분석 영역을 나누는 2열 구조다.
- 820px 이하에서는 두 영역을 단순히 세로로 쌓는다. 이 방식은 사용자가 긴 종목 목록을 지나야 선택한 분석 내용을 볼 수 있다.
- 모바일에서 종목을 선택해도 분석 영역으로 명확히 전환되거나 돌아오는 동작이 없다.
- `.watchlist`의 데스크톱용 `100vh`, sticky, 내부 스크롤 규칙과 모바일 override가 여러 CSS 파일에 나뉘어 있다.

### 3.2 CSS 소유권과 브레이크포인트

- `styles.css`에는 1180px, 820px, 560px 기준이 있다.
- `research.css`에는 1220px, 920px, 860px, 820px, 760px, 640px, 580px 기준이 섞여 있다.
- 같은 컴포넌트가 두 파일에서 반복 정의되어 변경 순서에 따라 결과가 달라질 수 있다.
- 모바일 작업에서 새 미디어쿼리를 계속 추가하면 우선순위 문제가 더 커지므로 기존 반응형 규칙부터 정리해야 한다.

### 3.3 공개 종목 분석

- 공개 분석 카드는 모바일에서 한 열로 바뀌는 부분이 있지만, 카드 내부 여백과 제목 크기가 작은 화면에 비해 크다.
- 오른쪽 고정 목차는 920px 이하에서 사라져 모바일에서는 긴 분석의 01·02·03 구간으로 바로 이동할 방법이 없다.
- 지표별 상태 해설이 모두 펼쳐져 있어 종목 하나의 페이지가 지나치게 길어진다.
- 근거 칩은 클릭 가능하지만 일부가 일반 텍스트처럼 보이며, hover에 의존하는 표현이 있다.

### 3.4 관리자 차트와 점수 패널

- SVG 차트는 920 단위 viewBox를 사용하고, 현재 휴대전화에서 최소 760px 너비를 요구한다.
- 차트 내부 가로 스크롤 자체는 관리자 연구 화면에서는 허용할 수 있지만, 페이지 전체의 가로 스크롤로 번지면 안 된다.
- 기간 선택과 지표 레이어 버튼이 여러 줄로 쌓이며 차트보다 먼저 많은 높이를 차지한다.
- 점수 패널과 세부 수치는 모바일에서 정보 우선순위가 정리되지 않은 채 모두 한 열로 늘어진다.

### 3.5 모의투자 성과

- 포트폴리오 요약은 모바일 한 열 처리가 일부 있지만, 7개 수치가 연속으로 길게 표시된다.
- 체결 기록과 주문 큐는 테이블 기반이라 작은 화면에서 열 제목과 값의 관계를 확인하기 어렵다.
- 새로고침 상태 문구와 버튼이 좁은 헤더에서 불안정하게 줄바꿈될 수 있다.

### 3.6 팝업

- 면책, 지표 교육, 근거 해설 팝업의 크기와 여백이 JSX 인라인 스타일로 고정돼 있다.
- 모바일 주소창과 안전영역을 고려한 `dvh`, 하단 safe area 처리가 없다.
- 긴 팝업에서 닫기 버튼이 스크롤 위쪽으로 사라질 수 있다.
- `role="dialog"`, `aria-modal`, 제목 연결, Escape 닫기와 같은 기본 접근성 동작을 정리할 필요가 있다.

### 3.7 법적 문서와 고정 고지

- 법적 문서 카드 폭은 통일됐지만 작은 화면의 영웅 영역, 탭, 하단 액션은 추가 압축이 필요하다.
- `.compliance-dock`은 모바일에서도 화면 하단에 고정되어 본문과 모바일 브라우저 UI를 가릴 수 있다.
- CMP가 실제로 로드되지 않은 동안에도 쿠키 설정 버튼이 노출되어 눌러도 반응이 없는 문제가 있다.

### 3.8 광고 영역

- 광고는 승인 전 미리보기이지만 모바일에서 목록과 본문 흐름을 지나치게 끊지 않는 높이 기준이 필요하다.
- 광고를 고정·플로팅하거나 콘텐츠 버튼처럼 보이게 만들지 않는다.

## 4. 반응형 기준

브레이크포인트는 다음 세 단계로 통일한다.

| 범위 | 이름 | 기본 동작 |
| --- | --- | --- |
| `0–640px` | 휴대전화 | 목록/상세 한 화면 전환, 단일 열, 터치 우선 |
| `641–920px` | 태블릿·좁은 화면 | 목록/상세 한 화면 전환, 일부 2열 카드 허용 |
| `921px 이상` | 데스크톱 | 현재 2열 목록+분석 구조 유지 |

`1220px`은 관리자 차트와 점수 패널의 2열/1열 전환 용도로만 유지한다. 나머지 1180·860·820·760·580·560 규칙은 위 기준으로 합치거나 명확한 컴포넌트 전용 규칙으로 제한한다.

필수 확인 화면 크기:

- 320 × 568: 최소 지원 폭
- 360 × 800: 소형 Android
- 390 × 844: 일반 iPhone 기준
- 430 × 932: 대형 휴대전화
- 768 × 1024: 태블릿 세로
- 1024 × 768: 태블릿 가로/소형 데스크톱
- 1440 × 900: 데스크톱 회귀 확인

## 5. 모바일 정보 구조

### 5.1 휴대전화·태블릿의 기본 흐름

모바일에서는 데스크톱의 두 열을 다음 두 화면 상태로 사용한다.

1. `목록 화면`
   - 간결한 브랜드 헤더
   - 검색 및 필터
   - 시장 요약
   - 종목 카드 목록
   - 더 불러오기
2. `상세 화면`
   - `종목 목록으로` 버튼
   - 선택 종목명·코드·점수 요약
   - 공개 분석 또는 관리자 차트
   - 광고 영역
   - 법적 고지

React Router나 별도 URL은 추가하지 않는다. `ResearchApp`에 `mobilePane: 'list' | 'detail'` 상태 하나를 두고 다음처럼 사용한다.

- 종목을 선택하면 `detail`로 변경한다.
- 목록으로 버튼을 누르면 `list`로 변경한다.
- 데스크톱 CSS에서는 상태와 관계없이 목록과 분석을 모두 표시한다.
- 모바일 CSS에서만 현재 pane을 표시한다.
- 공개 데이터 재로딩, 검색 결과 변경, 관리자 화면 전환 시 선택 상태와 pane이 어긋나지 않게 한다.

### 5.2 브라우저 뒤로가기

첫 구현에서는 history state를 추가하지 않는다. 화면 안의 명시적인 `목록으로` 버튼을 제공한다. 실제 사용자 테스트에서 브라우저 뒤로가기를 기대하는 혼동이 확인되면 그때 `history.pushState`를 추가한다.

## 6. 화면별 변경 계획

### 6.1 종목 목록

변경 위치: `frontend/src/ResearchApp.jsx`, `frontend/src/research.css`

- 모바일용 상단 행에 브랜드 축약명, 전체 종목 수, 새로고침 버튼을 배치한다.
- 데스크톱의 큰 브랜드 카드는 휴대전화에서 여백과 설명을 줄인다.
- 검색 입력은 필터가 접혀 있어도 항상 접근 가능하게 한다.
- 시장·상태·정렬·테마는 기존 `필터·정렬 펼치기` 안에 유지한다.
- 필터 열림 상태는 종목 선택 후 상세 화면으로 이동할 때 자동으로 닫아 분석 시작 위치를 안정화한다.
- 종목 행의 최소 터치 높이를 48px 이상으로 둔다.
- 선택 종목에는 색상만이 아니라 테두리와 `aria-current` 또는 동등한 상태를 제공한다.
- 종목명은 한 줄 말줄임, 코드·시장·상태는 두 번째 줄로 유지한다.
- 점수 배지는 최소 52px 폭을 유지하되 카드 본문을 밀어내지 않게 한다.
- `다음 30개 불러오기`는 목록 끝의 전체 너비 버튼으로 만든다.
- 목록 광고는 5개마다 유지하되 휴대전화에서 콘텐츠 카드와 구분되는 `광고` 라벨과 일정한 최소 높이를 둔다.

### 6.2 상세 화면 상단

변경 위치: `frontend/src/ResearchApp.jsx`, `frontend/src/research.css`

- 모바일 전용 상세 내비게이션을 분석 영역 최상단에 둔다.
- `← 종목 목록` 버튼, 선택 종목명, 점수/상태를 한 행 또는 두 행으로 표시한다.
- 이 영역은 `position: sticky`와 `top: 0`을 사용하되 모바일 safe area를 반영한다.
- 기존 데스크톱 topbar의 서비스명·로그인·관리자 전환은 모바일에서 다음 순서로 쌓는다.
  1. 목록으로 및 종목 정보
  2. 공개/관리자 화면 전환
  3. 로그인 상태와 로그인 버튼
- 장문의 로그인 상태 문구는 한 줄로 자르고 전체 내용은 접근 가능한 제목 또는 보조 문구로 남긴다.
- 고지 패널 두 개는 아이콘과 제목이 겹치지 않게 단일 열로 만들고 중복 문장을 합칠지 구현 전에 최종 문구를 검토한다.

### 6.3 공개 분석 상세

변경 위치: `frontend/src/ResearchApp.jsx`, `frontend/src/analysisEducationContent.jsx`, `frontend/src/research.css`

- 패널 외곽 여백을 휴대전화 16px, 태블릿 24px 수준으로 조정한다.
- 종목명, 코드, 분석 기준일, 점수, 분류를 세로 우선으로 정렬한다.
- 01 종합 해석의 3개 요약 카드는 휴대전화 한 열, 넓은 휴대전화/태블릿 두 열 또는 세 열로 자연스럽게 흐르게 한다.
- 02 반영 조건의 긍정/주의 영역은 한 열로 쌓는다.
- 근거 항목은 텍스트 칩이 아니라 최소 44px 터치 영역을 가진 버튼으로 통일한다.
- 오른쪽 hover 목차는 모바일에서 없애지 않고 같은 markup을 상단의 가로 스크롤 목차로 바꾼다.
- 목차는 `01 종합 해석`, `02 반영 조건`, `03 지표별 해설`을 표시하고 선택 시 기존 `scrollIntoView`를 재사용한다.
- 03 지표별 해설은 긴 목록을 줄이기 위해 각 지표를 native `<details>`로 전환한다.
- 지표명과 현재 상태는 접힌 상태에서도 보이고, 설명과 이유 버튼은 펼쳤을 때 표시한다.
- 첫 지표를 자동으로 열지 않는다. 사용자가 필요한 지표만 선택하게 한다.
- 교육 문구, 자체 점수, 공개 금지 수치 범위는 변경하지 않는다.

### 6.4 관리자 차트

변경 위치: `frontend/src/ResearchApp.jsx`, `frontend/src/research.css`

- 공개 이용자에게는 차트가 보이지 않는 현재 권한 경계를 그대로 유지한다.
- 기간 버튼과 지표 레이어 버튼은 각각 가로 스크롤 가능한 한 줄 도구막대로 만든다.
- 차트 SVG는 페이지 폭을 늘리지 않고 `.chart-frame` 내부에서만 가로 스크롤되게 한다.
- 휴대전화에서는 차트 내부 최소 너비를 680px 전후로 유지해 캔들·축 라벨을 읽을 수 있게 한다.

  2. 리스크 신호
  3. 점수 요소
  4. 세부 수치

## 8. 접근성·사용성 기준

- 주요 버튼과 선택 가능한 근거 항목의 터치 영역: 최소 44×44px
- 입력 글자 크기: iOS 자동 확대를 막기 위해 휴대전화에서 16px 이상
- 키보드 focus 표시 유지
- 색상만으로 선택·위험 상태를 구분하지 않음
- 모든 아이콘 단독 버튼에 `aria-label` 제공
- 현재 탭/선택 종목에 `aria-current` 또는 `aria-selected` 제공
- 팝업의 제목, 역할, 닫기 방식 제공
- 모바일 가로 방향에서도 상단 고정 영역이 본문 대부분을 가리지 않음
- `prefers-reduced-motion`에서는 smooth scroll과 불필요한 애니메이션 축소
- 200% 텍스트 확대 시 핵심 버튼과 문구가 잘리지 않음

## 9. 로컬 실행과 확인 방법

```powershell
Set-Location Mesugak_V2\frontend
npm run dev -- --host 0.0.0.0 --port 5173
```

- PC에서는 `http://127.0.0.1:5173`로 접속한다.

1. PC와 휴대전화를 같은 네트워크에 연결한다.
2. PC의 로컬 IPv4 주소를 확인한다.
3. 휴대전화에서 `http://<PC의 IPv4>:5173`으로 접속한다.
4. Windows 방화벽이 연결을 막으면 Node/Vite의 사설 네트워크 접근만 허용한다.

실제 휴대전화에서는 다음을 중점 확인한다.

- 주소창이 접히고 펼쳐질 때 레이아웃 높이
- 안전영역과 하단 고지
- 세로 스크롤 중 sticky header
- 종목 카드와 근거 버튼의 터치 정확도
- 팝업 내부 스크롤

- 공개 분석의 01·02·03 목차는 모바일에서 가로 스크롤 가능한 터치 rail로 바뀐다.
- 지표별 해설은 모바일에서 native `<details>`로 접힌 상태로 시작하고, 한 항목씩 펼칠 수 있다.
- 지표 교육 팝업과 근거 설명 팝업은 모바일 bottom sheet, 데스크톱 대화상자 형태로 공통 동작한다.
- 차트는 페이지 전체가 아니라 `.chart-frame` 내부에서만 가로 스크롤한다.
- 체결 로그와 주문 큐는 640px 이하에서 `data-label` 기반 카드형 표로 전환된다.
- compliance dock은 모바일에서 본문을 가리지 않는 footer 흐름으로 배치된다.
