## 2. Firebase 무료 운영·최소 저장 계획

### 2-A. 현재 상태와 비용 경로 확정

1. 결제 연결·요금제·연결된 서비스·무료 기능 의존성을 읽기 전용으로 확인한다.
2. 지연된 사용량과 실제 청구 기간을 구분해 저장량, 읽기·쓰기·삭제, 인덱스와 전송량을 표로 만든다.
3. 학교 서버의 모든 쓰기 경로(일봉 분석, 공개 발행, 모의투자, 갱신 요청, 정리)를 추적한다.
4. 끝난 정리는 완료 마커를 우선 확인한다. 과거 85,673개라는 수치로 다시 전체 스캔하지 않는다.
5. Spark 상태를 유지할 수 있는 기능 구성을 확정한다. 무료 한도 도달 시 갱신 중단과 오래된 자료 표시를 허용하는 정책을 명시한다. 예산 알림이나 클라이언트 캐시만으로 무과금을 보장하지 않는다.

산출물: 비용 경로표, 현 상태 날짜, 무료 한도 대비 내부 운영 한도와 중단 조건.

### 2-B. 데이터 수명과 저장 위치

| 데이터 | 기본 설계안 | 삭제/축소 조건 |
|---|---|---|
| 분석 입력 OHLCV | 학교 서버 압축 캐시, 클라우드 복제 최소화 | 실제 최대 lookback + 워밍업 + 재시도 여유 검증 후 롤링 보관 |
| 공개 점수·해석 | 최신 정상 발행 결과만, 안정된 ID와 페이지 | 새 발행 검증 후 이전 결과 정리; 실패하면 마지막 정상본 유지 |
| 관리자 차트 | 필요한 필드·기간의 최신본; 현 130행 제한 적합성 검증 | 표시 기간/연산 필요량을 구분해 축소; 원래 지표 계산 입력을 잘라 결과를 바꾸지 않음 |
| 과거 strategy_candidates | 새 생성 없음, 기존 완료 여부 확인 | 이미 정리됐으면 추가 요청 없음 |
| 실행·실패 로그 | 작은 요약 30일, 실패 조사 자료 최대 90일 제안 | 운영 필요에 따라 확정; 매 실행 전체 결과 첨부 금지 |
| 완료 갱신 요청 | 완료 후 7일 제안 | pending/처리 중 제외, 관련 작업 종료 확인 |
| 계좌·체결·중복주문 방지 | 별도 보관 정책 | 자동 분석 청소에서 제외; 재실행 안전성과 복구 기간 검증 |
| 로컬 백업 | 기간·총량 상한; 현 2GiB/여유 1GiB 중단 조건 검토 | 복원 검증·유효한 최신본 보존 후 만료분 정리 |

기간은 설계 제안이며 이번에 적용하지 않는다. 거래일과 달력일을 구분한다.

### 2-C. 저장·삭제 요청 줄이기

- Firestore는 문서별 작업을 과금한다. 500개 삭제를 한 batch로 보내도 1개 삭제로 과금되지 않는다.
  BulkWriter도 비용 할인 기능이 아니다. gzip은 바이트를 줄이고, 문서 묶기는 문서 수를 줄인다.
- 동일 데이터 날짜·분석 버전·내용 해시이면 재저장하지 않는다. 해시 비교 때문에 전량 읽지 않도록 서버 발행 상태를 활용한다.
- 여러 변경을 모아 최종 상태를 한 번 저장하고, 공개 조회 단위와 맞는 크기로 묶는다.
  문서 1MiB 한도, 인덱스 크기, 매번 전체 페이지 재전송 비용을 측정한다.
- 필요한 필드만 보관하고 조회하지 않는 이력·대형 배열의 인덱스 제외를 검토한다. 실제 쿼리 의존성을 먼저 확인한다.
- 즉시 삭제는 화면에서 만료 숨김과 물리 삭제로 구분한다. 물리 삭제는 다음 제한된 유지보수 시점에 모아 수행한다.
- 만료 대상만 커서 조회하고 작업 수·재시도·시간 상한을 둔다. 계정·거래 컬렉션은 별도 허용 목록으로 보호한다.
- TTL/관리형 대량 삭제의 비용과 Spark 지원 여부를 검토한다. 유료 기능을 편의상 켜지 않는다.
- 공개 결과 정적 JSON 제공은 대안으로만 비교한다. Firestore 읽기를 Hosting 전송량·배포 저장량으로 옮기므로 무조건 무료라고 판단하지 않는다.

### 2-D. 검증과 이후 적용

작은 로컬 샘플로 동일 데이터 재실행 시 쓰기 0, 지표 결과 동일, 공개 필드 경계,
실패 시 정상본 유지, 정리 재실행 시 작업 0, 복원 가능 여부를 검증한다.
학교 서버 반영 전 변경 파일과 롤백을 준비하고, 최신 한도에 맞는 소량 실행으로 측정한다.
완료 기준: 불필요한 결제 연결/유료 기능 없음, 데이터 총량이 내부 한도 이내,
반복 저장·정리 요청이 상한 내, 다음 정상 분석과 만료 처리까지 확인.

## 3. AdSense와 교육 콘텐츠 개선 계획

### 원인 분류

사용자가 받은 반려 사유는 게시자 콘텐츠 없는 화면 및 가치가 낮은 콘텐츠다.
공식 정책은 미검토·미선별 자동 생성 콘텐츠의 광고 배치를 주의 대상으로 명시한다.
자동 계산 기능 자체의 전면 금지라고 해석하지 않는다. 실제 심사 URL·시점·계정 사유를 확보한 뒤 진단한다.

기존 점검 문서의 후보 문제: 짧고 반복되는 설명, 예시 게시자 ID와 ads.txt 불일치,
준비 중 광고 표시, 미설정 후원 링크, 초기 HTML 본문 부재, robots/sitemap 오응답, 없는 URL의 200 응답.
이는 당시 발견이며 현재 배포본을 확인한 후 확정한다. 기술 SEO 오류와 콘텐츠 품질 문제는 구분한다.

### 개선 순서

1. 경로별로 사용자 가치·원작성·수동 검토·광고 요청·로그아웃 접근을 기록한다.
2. 자동 분석 도구와 사람이 편집한 학습 글을 명확히 연결한다. 광고는 우선 완성된 편집 글에 한정한다.
3. 기존 6개 지표 글에 직접 만든 계산 예제·도표·해석 과정·실패 사례·출처를 추가한다.
   첫 사례 글 4~6개는 내부 편집 목표이며 Google 최소 글 수 규칙이 아니다.
4. 방법론을 실제 점수 코드와 대조하고 데이터 부족·중복 근거·사용하지 않는 가치지표를 정확히 설명한다.
5. 글 작성/검토 주체·수정일을 실제 작업에 맞춰 기록한다. AI 초안 여부와 무관하게 검토 없이 대량 발행하지 않는다.
6. 학습 글을 빌드 시 정적 HTML로 제공하는 최소 변경을 설계한다. 상시 SSR·Functions를 추가하지 않는다.
7. 고유 제목·canonical·정상 robots/sitemap·진짜 404·작동하는 링크를 확보한다.
8. 실제 게시자 ID, ads.txt, 별도 광고 단위 ID, CMP 동의/거부/철회를 확인한다.
9. 빈 화면·오류·검색 조작·관리자·미검토 자동 분석에 광고 요청이 없는지 검증한다.
10. 4번 UX 검증 후 운영자 확인과 재심사 요청을 진행한다. 승인 전 광고 활성화나 재심사 제출은 이번 계획에 포함되지 않는다.

완료 기준: 편집 검토된 원문과 사례, 공개 직접 진입 정상, 미완성 표시 없음,
정책상 제외 화면 광고 요청 0, 비용 기준 충족. Google 승인 자체는 완료 보장 대상이 아니다.

## 4. 모바일·PC UI/UX 계획

별도 클라이언트를 두 벌 만들지 않고 현재 React 웹을 반응형으로 개선한다.

1. 기존 구현을 기준으로 홈→학습→종목 찾기→근거 확인→목록 복귀 여정을 재현하고 불편을 기록한다.
2. 모바일은 목록/상세 한 화면 전환, PC는 목록+본문 병렬을 유지한다. 검색·정렬·선택·스크롤·브라우저 뒤로 가기가 보존되게 설계한다.
3. 상세 해설은 제목·핵심 해석에 가장 큰 주목도, 조건의 뜻에 보조 주목도, 추가 확인점과 공통 면책에 낮은 주목도를 준다.
4. 근거 블록의 클릭 가능성을 명확히 하고 동일 설명을 공용 콘텐츠에서 불러온다. 그림·본문·용어를 사용자가 한곳에서 수정하도록 한다.
5. 모바일 팝업의 safe-area·닫기·내부 스크롤, PC 대화상자의 최대 폭·키보드 초점·Escape·초점 복귀를 점검한다.
6. 관리자 차트/표는 제한된 영역만 가로 스크롤한다. 공개 화면에 관리자 원시값이 노출되지 않게 한다.
7. 로딩·빈 결과·지연·오프라인 상태에서도 교육 콘텐츠는 읽히게 한다. 레이아웃 전환과 팝업이 추가 Firestore 요청을 만들지 않게 한다.
8. 광고·후원·쿠키 설정은 본문과 분리하고 가림·오클릭·레이아웃 이동을 방지한다.
9. 320/360/390/430/768/1024/1440px, 200% 확대, 터치·키보드·실제 휴대전화에서 검증한다.

산출물: 주요 화면 설계, 공용 컴포넌트/콘텐츠 변경 목록, 상태별 검증표.
완료 기준: 페이지 가로 넘침 없음, 목록 복귀 상태 보존, 팝업 접근성,
공개/관리자 경계 유지, 불필요한 읽기 증가 없음. 필요한 범위의 lint/build/정책 검증 후 배포를 검토한다.
