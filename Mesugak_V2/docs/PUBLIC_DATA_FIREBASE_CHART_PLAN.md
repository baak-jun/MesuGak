# 공공데이터·Firebase·차트 신호 전환 계획

작성 기준: 2026-08-30

## 1. 먼저 확정할 운영 원칙

1. 공개 분석의 시세 원천은 금융위원회 `주식시세정보`와 `지수시세정보`만 사용한다.
2. 공개 분석 배치는 국내 시장(KOSPI·KOSDAQ), 전일 확정 일봉만 처리한다.
3. KIS API는 운영자 본인의 모의투자 계좌 조회·모의주문에만 사용한다.
4. KIS 시세·분봉·원시 응답은 공개 분석, 공개 차트, 공개 Firestore 문서에 사용하지 않는다.
5. FinanceDataReader, yfinance, pykrx 등 비공식 수집 경로는 활성 V2 런타임에서 제거한다.
6. 예탁결제원 주식정보와 금융위원회 주식발행정보는 공공누리 제2유형이므로 AdSense가 있는 공개 서비스에는 별도 허가 전까지 사용하지 않는다.
7. 차트 신호는 먼저 기존 점수 규칙으로 구현하고, 성능상 필요가 입증된 뒤에만 소형 모델을 검토한다.

## 2. 현재 코드 점검 결과

| 항목 | 현재 상태 | 필요한 조치 |
| --- | --- | --- |
| 공개 분석 시세 | `market_data.py`가 금융위원회 주식·지수 API 사용 | 서버 실호출 재검증 |
| 분석 작업 | `analyze_market.py`는 KR 전용이며 KIS를 import하지 않음 | 경계 회귀 테스트 추가 |

| 구버전 호환 코드 | 활성 V2 런타임에서 제거됨 | 서버 잔여 파일만 정리 |
| 미국 자동 작업 | 실행 파일 제거, 국내 분석만 유지 | 서버 US cron이 없는지 유지 확인 |
| 범용 KIS 시세 클라이언트 | 제거됨 | `kis_paper.py`만 유지 |

| 비공개 Firestore | 원시 분석, 계좌, 주문, 분봉 상태는 관리자 전용 | 권한 거부 테스트 유지 |

| 관리자 차트 | 기존 SVG 캔들·밴드·이평·RSI 차트가 있음 | 같은 SVG에 신호 마커 추가 가능 |

## 3. 단계별 작업 순서

### 단계 A. 학교 서버 사전 점검

목표: 파일 복사뿐 아니라 실행 환경 전체가 정상인지 확인한다.

- 디스크 여유, Python 가상환경, 설치 패키지, cron, `flock`, 로그 디렉터리를 확인한다.
- 키 값은 출력하지 않고 다음 항목의 존재 여부만 확인한다.
  - `DATA_GO_KR_SERVICE_KEY`
  - Firebase Admin 서비스 계정 또는 Application Default Credentials
  - KIS paper 전용 키·계좌 환경변수
  - Gmail 앱 비밀번호와 수신 주소
- 공공데이터 주식 API에서 삼성전자 1종목 일봉을 읽는다.
- 공공데이터 지수 API에서 KOSPI·KOSDAQ 기준값을 읽는다.
- `analyze_market.py --market KR --codes 005930,000660 --dry-run`을 수행한다.
- 기존 체크포인트와 실행 중 프로세스를 확인한 뒤에만 전체 작업을 실행한다.

완료 기준:

- 두 공공 API가 HTTP·업무 오류 없이 응답한다.
- 2종목 dry-run이 실패 0건으로 끝난다.
- 서버 시간이 Asia/Seoul이고 cron 진입 경로가 실제 설치 경로와 일치한다.
- 디스크가 로그·체크포인트를 안전하게 기록할 여유가 있다.

### 단계 B. 비공식 데이터 경로 제거

목표: 실수로도 비공식 공급자를 호출할 수 없게 만든다.

- 활성 V2 배포물에서 `server_runtime/v1_compat/`를 제거한다.
- `run_v2_us_close.sh`와 서버의 US cron 항목을 제거한다.
- 호출자가 없는 `strategy_engine/kis_api.py`와 해당 테스트를 제거한다.
- 문서의 FinanceDataReader·KIS 분석 경로 설명을 현재 공공데이터 경로로 바꾼다.
- CI에 금지 문자열 검사를 추가한다.
  - `FinanceDataReader`, `yfinance`, `pykrx`, `pandas_datareader`, `investpy`
- 보존 대상인 저장소 최상위 `Mesugak_V1/`은 역사적 참고 버전이므로 이 단계에서 수정하지 않는다.

완료 기준:

- V2 Python·shell·requirements 검색 결과에 금지 패키지의 실행 코드가 0건이다.
- KR 분석 테스트와 전체 백엔드 테스트가 통과한다.
- 서버 cron에는 KR close, health monitor, KIS paper worker만 남는다.

### 단계 C. KIS를 모의투자 전용으로 강제

목표: 설정 실수나 향후 리팩터링으로 KIS 시세가 공개 분석에 섞이는 것을 막는다.

- KIS 코드는 `kis_paper.py`와 `school_paper_trader.py` 아래의 모의투자 기능으로만 유지한다.
- base URL은 `openapivts.koreainvestment.com`만 허용하고 실전 URL이면 즉시 실패시킨다.
- 환경변수도 `KIS_PAPER_*`만 허용하고 범용·실전 키 fallback을 없앤다.
- 정적 경계 테스트를 추가한다.
  - `analyze_market.py`, `market_data.py`, `publish_public_analysis.py`는 KIS 모듈 import 금지
  - 공개 요약 allowlist에는 OHLCV, 분봉, 계좌, 주문, 토큰 필드 금지
- KIS 계좌·주문·현재가 조회 결과는 관리자 전용 컬렉션에만 저장한다.
- 공개 문서의 `source`에는 KIS 문자열이 나타나지 않게 한다.

완료 기준:

- public 분석은 KIS 키가 전혀 없는 환경에서도 끝까지 실행된다.
- KIS paper 작업은 공공데이터 키가 없어도 모의계좌 기능만 수행한다.
- 실전 KIS URL 또는 실전 키를 넣은 테스트가 fail-closed로 종료된다.

### 단계 D. Firebase 갱신 경로 단순화

목표: 전체 분석이 끝난 뒤 완전한 공개 스냅샷 하나만 노출한다.

- `analyze_market.py`는 비공개 `stock_analysis`, `meta_data`, 실행 상태만 기록한다.
- `publish_public_analysis.py`만 공개 페이지와 manifest를 작성한다.
- 공개 페이지를 먼저 모두 기록하고 manifest를 마지막에 갱신한다.
- manifest에는 데이터 기준일, 발행 시각, 종목 수, 페이지 수, 소스 코드만 넣는다.
- 기존 공개 페이지 수가 줄었을 때 남는 문서를 정리한다.
- Firestore 규칙은 다음을 유지한다.
  - 익명: 명시된 KR 공개 페이지와 manifest만 `get`
  - 관리자: 원시 분석·차트·모의투자 문서 읽기
  - 브라우저: 서버 소유 문서 쓰기 금지
- 전체 KR close 작업이 성공한 경우에만 health monitor 성공 시각을 갱신한다.

완료 기준:

- 로그에 전체 분석 완료, 공개 발행 완료, monitor 성공이 순서대로 남는다.
- 익명 브라우저에서 공개 manifest와 첫 페이지가 읽힌다.
- 익명 브라우저에서 `stock_analysis`와 paper 컬렉션은 `permission-denied`가 발생한다.
- 중간 실패 시 이전 manifest가 계속 유효하고 불완전한 새 목록을 가리키지 않는다.

### 단계 E. 차트 데이터의 공개 범위 결정

데이터 원천에 따라 화면을 분리한다.

| 데이터 | 관리자 화면 | 공개 화면 |
| --- | --- | --- |
| 금융위원회 전일 일봉 | 가능 | 이용허락 제한 없음 표시를 근거로 검토 가능 |
| KIS 일봉·분봉·현재가 | 모의투자 연구용으로만 가능 | 정보이용계약 또는 서면 허가 전까지 금지 |
| 공공누리 제2유형 예탁·발행정보 | 비상업 연구용 검토 가능 | AdSense 서비스에는 허가 전까지 금지 |

공개 일봉 차트를 추가하기 전 확인할 사항:

1. 공공데이터포털 또는 제공기관에 실제 화면 예시를 첨부해 종목별 OHLC 캔들 재표시와 광고 포함 여부를 서면 문의한다.
2. 현재 개인정보처리방침·서비스 이용안내의 “가격·차트 비공개” 문구를 실제 기능과 맞게 변경한다.
3. 화면 하단에 데이터 출처, 기준일, 일 1회 갱신, 투자권유가 아니라는 점을 표시한다.

이 확인이 끝나기 전에는 새 마커 차트도 관리자 화면에서만 제공한다.

### 단계 F. 규칙 기반 차트 마커 MVP

목표: 새 AI 없이 기존 전략이 어떤 날짜에 높은 점수를 냈는지 설명한다.

- 일별 OHLCV에 현재 `indicators.py`, `scoring.py`, `risk.py`를 같은 순서로 적용한다.
- 각 날짜의 계산은 그 날짜까지의 데이터만 사용한다. 미래 데이터가 섞이면 실패하는 테스트를 둔다.
- 마커 최소 스키마:

```text
date
scoreBand       # high / watch / defensive
score           # 관리자만 숫자 공개 여부 선택
reasonCodes[]   # 해당 날짜에 실제 발동한 조건
shape           # circle / square
position        # above / below
```

- 기본 표현:
  - 원: 여러 긍정 조건이 동시에 확인된 날
  - 사각형: 위험·방어 조건이 확인된 날
  - 마커 클릭/탭: 점수보다 “왜 표시됐는지” 이유 문장을 우선 표시
- 기존 `TechnicalChart` SVG의 `xForIndex`, `yForPrice`를 재사용해 `<circle>` 또는 `<rect>`를 추가한다.
- 새 차트 패키지는 추가하지 않는다.

완료 기준:

- 동일 입력에 동일한 마커가 생성된다.
- 모바일에서 마커를 탭할 수 있고 차트 가로 overflow가 없다.
- 320, 390, 768, 1440px에서 표시와 팝업을 확인한다.
- 공개 문서에는 허용한 필드 외의 원시 지표 수치가 섞이지 않는다.

### 단계 G. 규칙의 실제 유용성 검증

목표: 보기 좋은 표식이 아니라 재현 가능한 분석 신호인지 확인한다.

- 과거 시점 순서대로 walk-forward 검증을 한다.
- 마커 이후 5·10·20영업일 성과를 측정한다.
- 최소 지표:
  - 신호 수
  - 상승 비율
  - 평균·중앙 미래수익률
  - KOSPI/KOSDAQ 대비 초과수익
  - 최대낙폭
  - 위험 마커의 손실 회피율
- 거래비용과 다음 거래일 체결 가정을 적용한다.
- 종목·기간을 보고 규칙을 반복 조정한 결과와 최종 검증 구간을 분리한다.

완료 기준:

- 규칙별 표본 수와 성능이 보고서로 남는다.
- 특정 종목 한두 개가 아니라 여러 기간·종목에서 재현되는지 확인한다.

### 단계 H. 소형 모델은 조건부로만 도입

다음 조건을 모두 만족할 때만 진행한다.

1. 규칙 기반 기준선이 구축되어 있다.
2. 해결할 실패 유형이 수치로 정의되어 있다.
3. 모델이 그 실패를 시간 외 검증 구간에서 실제로 줄인다.

첫 후보는 신경망이 아니라 로지스틱 회귀 또는 작은 gradient boosting 모델이다.

- 입력: 기존 지표 상태, 점수 구성요소, 위험 플래그, 변동성 상태
- 목표: 5·10·20일 뒤 위험조정 성과의 구간 분류
- 분할: 무작위 분할 금지, 날짜 기준 train/validation/test
- 금지: KIS 분봉으로 학습한 공개 결과를 권리 확인 없이 배포
- 표시: 모델 확률을 매수확률로 부르지 않고 분석 일치도 또는 패턴 유사도로 표현

모델이 단순 규칙보다 명확히 낫지 않으면 배포하지 않는다.

## 4. 실제 진행 단위

1. 서버 사전 점검 및 공공 API·Firestore 실연결 확인
2. 비공식 경로와 US 작업 제거
3. KIS paper 전용 경계와 회귀 테스트 적용
4. 공개 발행 경로 단일화 및 Firebase 규칙 검증
5. 전체 KR close 1회 실행과 익명 웹 확인
6. 관리자 전용 규칙 기반 일봉 마커 구현
7. 과거 검증 보고서 작성
8. 공공데이터 차트 공개 범위 서면 확인
9. 허용 범위에 따라 공개 차트 또는 관리자 전용 유지 결정
10. 필요가 입증된 경우에만 소형 모델 실험

## 5. 이번 전환에서 하지 않을 것

- KIS 분봉을 공개 캔들 차트에 표시하지 않는다.
- 제2유형 공공데이터를 AdSense 화면에 넣지 않는다.
- 비공식 Python 금융 라이브러리 fallback을 남기지 않는다.
- 미국 시장을 불완전한 데이터 소스로 유지하지 않는다.
- 첫 버전부터 패턴 인식 AI를 만들지 않는다.
- 기존 `Mesugak_V1/` 보관본을 이번 V2 운영 정리와 함께 수정하지 않는다.
